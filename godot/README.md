# Godot v0.2.1 · OPC 与现金流原型

Godot 4.5.1 标准版，Windows 2D/GDScript/Control，中文、鼠标键盘、单人离线，无第三方库。当前为开发工程运行，尚无独立 EXE。

## 运行与最短试玩路径

仓库根目录双击 `试玩原型.cmd`，或导入本目录 `project.godot` 后按 F5。启动器使用本机已有引擎的相对路径，换机器时可指定：

```powershell
& ./godot/运行原型.ps1 -Godot '本机/Godot_v4.5.1-stable_win64.exe'
& ./godot/验证.ps1 -Godot '本机/Godot_v4.5.1-stable_win64.exe'
```

1. 从东亚、西欧或北美西岸创业：创始人 1、雇员 0、现金 ¥40。
2. 看板接“整理客户表格”→“自己开工”→工作完成后“交付收款”。开工后按模拟时间持续处理，不用连续点鼠标。
3. 花 ¥60 买高效工作台，创始人效率翻倍，解锁批量单和企业单。延期回款先列入应收，到期才增加现金。
4. 留出现金，支付 ¥180 完成首雇。员工自动处理和交付已接订单，工资按在岗模拟日累计。
5. 买 ¥120 接单流程，开启自动接单；可切换短单/批量单/企业单偏好。优先接偏好订单，额度或资金不足时自动补接更小订单；补单不改变偏好。收费单预留下一次账单，零启动费短单可用于现金紧张时恢复业务。
6. 主动开启“地图招聘”，进入“世界地图”收简历、用招聘点买原有三条能力路线、处理职场事件。自动接单与原有招聘共用同一模拟时间。
7. “现金流”显示现金、应收、账单、三周预估和最近交易；打开自动暂停，关闭恢复原暂停状态。

空格暂停/继续，1×/2×/4×。暂停时仍可安排接单、升级和雇佣，工作与账单停止；事件和重开确认停止推进。金融阅读页内不执行经营动作。暂停新招聘不停止既有工资和业务。

本周需求有上限：例如仅剩30工作量时，90工作量企业单暂不可接，自动化会补接两笔12工作量短单；剩6时等待下一周，额度刷新后恢复优先接企业单。看板显示刷新倒计时，禁用按钮和空闲订单区显示等待原因。员工较多时会更快用完周需求，等刷新期间仍会计薪。

v0.2.1兼容现有v2存档，正常退出并重新打开游戏即可加载修复，无需重新创业。

## 本版参数和账目口径

金额以整数分存储，界面显示虚构游戏元；参数集中在 `data/content.json` 的 `economy`、`tools`、`orders`。

| 项目 | v0.2 参数 |
| --- | --- |
| 初始资金 | ¥40；当前只提供 OPC 一种模板 |
| 财务周 | 60 模拟日；1× 下约 60 现实秒；关闭游戏无离线收益 |
| 整理客户表格 | 工作量 12，启动费 0，交付到账 ¥30 |
| 批量资料整理 | 工作量 36，启动费 ¥5，报酬 ¥105，交付后 15 模拟日到账 |
| 企业数据服务 | 工作量 90，启动费 ¥20，报酬 ¥300，交付后 60 模拟日到账 |
| 产能 | 创始人开工 1 工作量/日，工作台后为 2；雇员每人 0.6/日 |
| 工资 | 每人 ¥6/周，按本周每日在岗人数累计后四舍五入到分 |
| 运营费 | ¥6/周，加每个有雇员地区 ¥2/周；创始人所在地区至少计 1 地区 |
| 市场需求 | 起始及已覆盖地区人口合计 ×3 工作量/周，接单消耗、周结后刷新 |
| 欠款 | 不隐式透支现金；首次不足启动固定两周救援期，部分回款或再次欠款不延期；实际到账优先补欠款 |

同日顺序：到期应收到账→执行/交付→计入当日在岗人数→到周末发薪与付运营费→检查欠款期限。招聘增长在本日费用累计之后发生，新增加的人数从下一日开始计薪。收入按实际回款进入现金；工具、首雇准备费和订单启动费立即扣现金。

三周预估固定当前人数，只计已交付应收与已知/预计费用，不包含未完成订单或未来新订单，因此可能显示缺口；这是保守预估，不是自动经营收入承诺。全球入职、反制及财务失败已接通；有欠款时不能获胜。

## 验证与存档

`验证.ps1` 使用 `.runtime/regression-v02` 隔离测试档，覆盖完整经营/招聘胜负、三个账目案例、暂停快进、财务页暂停恢复、订单与应收续局、随机状态、坏档保护和重开。窗口输入证据及覆盖范围见 `../qa/QA_REPORT.md`。

正常存档为 `user://hiring-v2.json`。工程与游戏名称变更后用户数据目录也不同；旧版 `hiring-v1.json` 不被读取或覆盖，本版不伪造旧档的经营状态。新档版本为 2；校验失败保留文件，明确确认重开后才允许覆盖。每 10 个模拟日、关键操作与退出时保存。

## 修改入口与剩余范围

- `simulation.gd`：唯一时间和状态、订单/工具/首雇/自动化、工资费用、市场需求、招聘、胜负与存档。
- `main.gd`、`main.tscn`：订单看板、地图、现金流面板、按钮、暂停与输入。
- `data/content.json`：经济参数、订单、工具，以及原有 12 地区/12 升级/4 事件。
- `tests/verify.gd`：机制和场景逻辑回归；真实系统输入单独实机验证。

当前共享一份订单队列，地区扩张增加需求上限与工资；不逐地区排单。欠款尚未增加专属员工离职效果。贷款、经济冲击、经营方针、资本市场、教学/设置完善、正式音画、独立包与跨机器验收待开展；真人完整获胜和平衡/趣味不由机制回归证明。
