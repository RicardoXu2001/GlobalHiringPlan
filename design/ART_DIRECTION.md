# 《夜班回路》（开发代号）美术圣经 · ART-2

targetFinish: 可在 Windows Godot 中完整游玩的重构切片，采用 ART-2 精细像素场景、角色、HUD 与反馈。

2026-11-12。用户确认[首批精灵样稿](visual-targets/sprite-review-v1/REVIEW.md)的造型与材质，随后明确否定整图式实机替换。本版保留 ART-2 风格目标，制作方式修正为模块化场景与真实动作；样稿确认不等于实机美术通过。Windows、固定斜俯视、现有战斗与关卡布局继续沿用。当前游戏为 0.2.1；完整战役范围见[产品范围](PRODUCT_BRIEF.md)，实机证据见 [QA](../qa/QA_REPORT.md)。

## 制作约束：可组装的场景，完整的动作

不得用整张房间图替代场景搭建，不得把静态人物母稿切成上下两段错动来充当动画。地面、墙段、柱、门、管线、前景和机械部件独立组合，按脚点排序处理遮挡。09 与敌人必须有身体、四肢和重心变化的关键姿态；握持点随帧变化，武器、命中与恢复跟随规则时钟。门扇、护板、活塞、锤臂和泵轮独立运动。

## 视觉语言：冷光工业，血肉显形

钢架包裹活体脏器，机械接口连接腱束与供给管。大形体先成立，再在板甲转折、受力关节、接口与磨损处增加细节。冷钢、哑光检修服、湿润组织各有明暗语言；不靠铺满纹理或扩大光晕制造精致感。

09 采用批准样稿的成人检修员比例、头灯、分层工作服与工具包，不再使用旧版四头身几何小人。免疫守卫以双盾、低头和外露腱束构成防守轮廓；感染工人为高瘦前倾人形；失败孵化体为低矮四足体；Boss 为固定心核与双活塞臂。敌我区别依靠体形、姿态和行为，不能只换颜色。

四项全局规则：

1. 关闭光晕仍能识别人、出口、敌人和交互物。先画实体亮芯，再加局部光。
2. 背景血肉是材质，危险必须另有警红边界、斜线或警告符号。
3. 地面保持宽阔低对比色块；细节集中在墙体与装置，给移动、脚点和预警留空间。
4. 后续所有资产继承本批材质、比例与功能色；同一设施变异时保留位置、接口和主轮廓。

风格参考为用户提供的[生体工厂原型板](visual-targets/夜班回路：生体工厂原型板.png)与[武器原型板](visual-targets/夜班回路：武器原型原型板_gbc.png)。输出采用本作设计，不复制特定游戏的角色、徽标与构图。

## 色板与光照层级

锁定以下**色系锚点及功能语义**。钢铁、布料和组织可在各自色系中使用连续明暗阶，不再要求生成母稿归并到恰好 16 色；UI 与规则提示仍使用下列固定 HEX。不得增加新的大面积功能霓虹色。

| 色系 | 锚点 | 角色与形状编码 |
| --- | --- | --- |
| 深墨／夜蓝 | `#07141F`、`#102738` | 背景空隙、文字底、远景，必经路径保留墙脚或灯线 |
| 冷钢／石板／雾钢 | `#244454`、`#49616B`、`#829499` | 装甲大面、倒角、短金属高光 |
| 骨白 | `#DFE8D5` | 正文、玩家受光面、极短命中芯 |
| 焦土／黄铜 | `#493B37`、`#897451` | 布料、旧漆、接口；非发光材质 |
| 血肉暗／肉灰 | `#492C42`、`#9C626C` | 组织阴影与实体，少量湿高光；不作为伤害编码 |
| 交互青 | `#237C83`、`#57E4CE` | 可操作显示窗、方括号、键位、弱点开启；可操作不代表可信 |
| 路标琥珀 | `#AA693A`、`#FFC46B` | 检修灯、出口、目标短线；不保证安全 |
| 警红 | `#FF526D` | 即时危险，配合边框、斜线、三角形 |
| 异常紫 | `#A58ADC` | 系统异常的小型错位轮廓；不承担必读文字 |

合成优先级：**玩家与危险边界 → 交互与目标 → 装置受光 → 气氛和光晕**。环境以暗部和中间调为主，高亮集中于少数接口。常规光晕半径约 4–12 渲染像素、透明度不高于 20%；不使用全屏 bloom。地面危险轮廓在装饰特效之后绘制。

## 镜头与可测量规格

世界玩法坐标为 **640×360 逻辑单位**，实际场景渲染为 **1280×720**，世界节点按 2 倍绘制。UI 单独按 1280×720 排版。提高画面细节不改变移动速度、攻击距离、碰撞盒和交互点。

1280×720 原生显示，2560×1440 为 2 倍；更大窗口使用能容纳的整数倍居中。1920×1080 当前显示 1280×720 场景并留边，UI 使用相同倍数与位置，保证世界内交互标签不偏移。低于 1280×720 会等比缩小；最小窗口 960×540，细节和文字可读性仍待专项验证。纹理使用最近邻采样，不能把母稿尺寸当作游戏内尺寸。

| 资产 | 逻辑包围框上限 | 720p 渲染上限 | 对齐规则 |
| --- | --- | --- | --- |
| 09 | 基准 32×48，出招／倒地宽可至 56 | 基准 64×96 | 同一片段共享缩放，逐帧记录脚点与握持点；倒地不拉高为站姿 |
| 感染工人 | 40×48 | 80×96 | 前倾人形，底部中央脚点 |
| 失败孵化体 | 54×38 | 108×76 | 四足低矮，扑击方向可读 |
| 免疫守卫 | 64×67 | 128×134 | 双盾宽肩，血条位于头顶 |
| 压维守卫／压力机 | 147×113 | 294×226 | 核心与脚底分开锚定，体积不等于可受伤范围 |
| 接驳台 | 129×112 | 258×224 | 空槽／心核状态共享底部锚点，搏动仅小幅缩放 |
| 门／终端 | 56×62／32×43 | 112×124／64×86 | 门开闭共享框架；终端显示窗小面积交互青 |
| 武器 | 普通 35×19；长探针 56×13 | 普通 70×38；长探针 112×26 | 保持长宽比，跟随握持点与出招方向 |
| 房间 | 640×360 布局 | 1280×720 | 地板以 62×42 模块拼接，墙段 46×60；程序管线与独立门／机械部件，不加载整房间 PNG |
| 商店图标 | — | 259×65 容器 | 等比居中，忽略母稿固有最小尺寸，不撑开卡片 |

| PixelFX | 原有 32／64／128 方形帧 | 按具体事件尺寸绘制 | 保留亮芯、透明背景和清晰危险边线 |

人物与物件绘制位置对齐 0.5 逻辑单位，即 1 渲染像素。危险边界通常 4 渲染像素，并有深色外衬；背景装饰不得达到同等对比。当前母稿具有较细的像素风格纹理，但没有经过严格统一源像素网格、索引色归并或逐像素手工清理，不将其描述为此类生产成品。

## UI、文字与图标

UI 延续检修终端：不透明深底、钢色细边、顶部短倒角亮线。焦点用骨白边框与交互青文字；不可用按钮保留原因。商品使用本批对应实物图，等比缩放，不缩成不可辨认的插画碎片。

720p 正文目标 20px、功能标签 18px、次要说明下限 16px；文字使用清晰中文无衬线，不压入世界图层。按钮目标热区至少 44×44，间隔至少 8px。提供 100／125／150% 字号及键盘焦点。工程目标为正文对比至少 4.5:1、关键图形至少 3:1；全部字号、色觉模拟和发行字体许可仍需专项检查。

常驻信息保持目标左上、短通知右上、耐久与闪避下方。读文面板不透明。菜单、暂停、选装、商店、失败和结果页继承同一容器语言；未来加载与宣传也沿用本规范，不另外改成厚涂、3D 或其他像素密度。

## 动作、特效与声音

规则窗口由游戏计时，动画不能改变命中判定。前摇先读出方向，接触时短亮芯、反冲与碎屑，随后迅速恢复地面可读性。现有 PixelFX 的斩击、脉冲、格挡、命中、Boss 压降／横扫、闪避、受伤、倒地与收集效果继续使用对应功能色。

当前 09 使用六帧前视、六帧后视行走与四组四帧动作，共 28 个姿态；挥击含反向蓄力、踏步、跟随与恢复，架枪含举起／反冲，闪避含低身与落地，死亡由踉跄、屈膝、着地到侧卧。三类小怪各 12 帧，包括四帧行走、两帧蓄力、两帧释放／恢复、受击与死亡。它们由游戏状态选择播放，不能通过拉伸静态图替代。Boss 护板开启、机械臂蓄力／落击、活塞连杆和心核搏动分别绘制。行走目标 8–12fps，事件窗口仍由规则决定。

本批为动作初版：行走有前后视，战斗动作目前为正面斜视并按左右镜像；完整背向／多方向战斗、每帧握持点和装备侧别仍待精修。不得宣称完整全方向动画已完成。

禁止全屏高频闪烁。受伤闪仅作用于人物，灯脉冲不超过 2Hz。低动效关闭震动、拖尾与亮度脉冲，保留固定轮廓、状态与结果。危险音优先于环境噪声，金属命中先短击再结构共振，生物命中为闷响；当前没有配音，也不新增音乐制作范围。

## 当前批次与后续纪律

`rpg/art/modular/` 保存六张新母稿，索引为 **64 个角色／敌人姿态帧**和 **12 个场景模块**；世界使用模块与程序部件组合。原 `painted/` 的整房间、人物和 Boss 定妆图保留作造型／材质参考，武器／装备图继续用于持物或 UI。标题、原序章、首组远征、中心和肺叶入口共用当前制作方式。

母稿保留原文件；`python rpg/art/index_modular.py` 只读 Alpha 并重建区域元数据，不修改、重采样或重新生成图片。生成记录见 [PROMPTS](../rpg/art/modular/PROMPTS.md)，首批确认记录见[样稿说明](visual-targets/sprite-review-v1/REVIEW.md)。运行时仅需 Godot，无生成服务依赖。旧绘图脚本保留作历史来源，不再决定当前人物与场景。

每批继承 ART-2，记录用途、源图、区域、显示包围框、锚点与动作状态；先看实际 720p 同屏效果，再扩产。尚未实现的六组、其他脏器、终极 Boss、全套加载／宣传资产不在本次完成范围。

禁用清单：彩虹霓虹、泛白 bloom、模糊精灵、纯黑必经路、背景与威胁同等对比、走道碎纹理、母稿撑破 UI、武器拉伸、逐帧身份变化、复刻其他游戏、用概念图冒充实机。

当前已在 1280×720 检查代表画面及由实际输入采样的动态预览，并通过两套原生输入回归；这只证明可运行与所列行为，不代表实机美术已获用户确认。真人手感、多 DPI、全屏、完整遮挡处理、所有字号及高分辨率显示专项仍待验证；详情见 [QA](../qa/QA_REPORT.md)。
